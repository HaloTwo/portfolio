## Project MORPG

> Unity 클라이언트와 C++ TCP 서버를 분리하여
> 클라이언트/서버 통신과 데이터 영속화 구조를 학습한 프로젝트입니다.

클라이언트가 계정 및 캐릭터 데이터를 직접 판단하지 않고
C++ 서버가 인증, 캐릭터 생성·삭제, 게임 입장,
원격 플레이어 동기화 흐름을 처리하도록 구성했습니다.

- **기간:** 2026.05 ~ 진행 중
- **기술:** Unity 6 · C# · C++17 · Winsock TCP Server · MariaDB
- **핵심:** Client/Server Separation · Packet Processing · DB Persistence · Multiplayer Synchronization

### 구현 내용

- LoginScene → LoadingScene → CharacterSelectScene → GameScene 흐름 구성
- Unity TCP Client와 C++ Winsock TCP Server 연결
- 텍스트 프로토콜 기반 요청/응답 패킷 처리
- NetworkManager / TcpServerConnection / PacketDispatcher 구조 분리
- TcpServer / ClientSession / PacketCodec / AuthService 구조 구현
- Repository Pattern 기반 MariaDB 접근 구조 구성
- 로그인 / 회원가입 / 캐릭터 생성 / 캐릭터 삭제 / 게임 입장 흐름 구현
- 계정당 캐릭터 3슬롯 구조와 `slot_index` 기반 슬롯 유지 처리
- 두 클라이언트 접속 시 원격 플레이어 Spawn / Move / Stop / Despawn 동기화
- 인게임 채팅 UI 및 TCP 채팅 송수신 흐름 구현

### 구현 방향

- Unity 클라이언트가 DB에 직접 접근하지 않고 서버를 통해 계정 및 캐릭터 데이터를 처리하도록 분리
- 네트워크 연결, 패킷 처리, 서비스 계층, Repository 계층을 나누어 각 역할을 분리
- 초기에는 Blocking TCP와 Text Protocol을 사용하되 추후 구조 확장이 가능하도록 구성
